# Техническое задание на разработку программного продукта для планирования встреч

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.

## User Stories
1. Регистрация нового сотрудника
Как новый сотрудник, я хочу зарегистрироваться в системе, чтобы получить доступ к планированию встреч.

2. Авторизация сотрудника
Как зарегистрированный сотрудник, я хочу войти в систему, чтобы получить доступ к своему аккаунту и функциям приложения.

3. Просмотр и редактирование профиля
Как сотрудник, я хочу просматривать и редактировать информацию в своем личном профиле (например, имя, должность), чтобы другие участники встреч могли меня идентифицировать.

4. Создание новой встречи
Как сотрудник, я хочу создать новую встречу, указав тему, описание, дату, час начала и продолжительность (в часах), а также выбрать приглашенных коллег, чтобы организовать совместное мероприятие.

5. Просмотр и ответ на приглашения
Как сотрудник, я хочу видеть список полученных приглашений на встречи и иметь возможность принять или отклонить каждое из них, чтобы управлять своим расписанием.

## Use Cases

1. Регистрация нового сотрудника
Актор: Новый сотрудник.
Предусловие: Сотрудник не авторизован в системе.
Основной поток:
- Сотрудник открывает экран регистрации.
- Система запрашивает email, пароль, имя и фамилию.
- Сотрудник вводит данные и подтверждает регистрацию.
- Система проверяет уникальность email, хэширует пароль и сохраняет данные нового пользователя.
- Система сообщает об успешной регистрации и автоматически авторизует пользователя.


2. Авторизация сотрудника
Актор: Зарегистрированный сотрудник.
Предусловие: Сотрудник имеет действующие учетные данные.
Основной поток:
- Сотрудник открывает экран входа.
- Система запрашивает email и пароль.
- Сотрудник вводит свои учетные данные.
- Система проверяет их соответствие данным в БД.
- При успехе система генерирует и возвращает токен доступа (JWT).
- Приложение сохраняет токен для последующих запросов.



3. Просмотр и редактирование профиля
Актор: Авторизованный сотрудник.
Предусловие: Сотрудник находится на экране своего профиля.
Основной поток (Просмотр):
Система отображает текущую информацию профиля (имя, фамилия, email, должность).

Альтернативный поток (Редактирование):
- Сотрудник нажимает кнопку "Редактировать".
- Система переходит в режим редактирования, позволяя изменить имя, фамилию, должность.
- Сотрудник вносит изменения и сохраняет их.
- Система отправляет обновленные данные на сервер и подтверждает успешное сохранение.


4. Создание новой встречи
Актор: Авторизованный сотрудник (организатор).
Предусловие: Сотрудник находится на экране создания встречи.
Основной поток:
- Организатор заполняет обязательные поля: "Тема", "Дата", "Час начала", "Продолжительность (в часах)". Опционально может добавить "Описание".
- Организатор выбирает из списка сотрудников одного или нескольких приглашенных.
- Система локально проверяет, что время начала кратно часу (например, 9:00, 10:00).
- Организатор подтверждает создание встречи.
- Система проверяет, что организатор и приглашенные свободны в указанный часовой слот.
- Система создает встречу в статусе "Ожидает ответа" и отправляет приглашения выбранным сотрудникам.


5. Просмотр и ответ на приглашения
Актор: Авторизованный сотрудник.
Предусловие: Сотрудник имеет непросмотренные или неотвеченные приглашения.
Основной поток (Просмотр):
- Сотрудник переходит на вкладку "Приглашения".
- Система отображает список приглашений с деталями (тема, организатор, дата/время, текущий статус).

Альтернативный поток (Ответ):
- Сотрудник выбирает одно из приглашений в статусе "Ожидает ответа".
- Сотрудник нажимает кнопку "Принять" или "Отклонить".
- Система обновляет статус участия сотрудника в этой встрече.

  Задачи для фронтенд-разработчика:

1. Создать экран авторизации:
   a. Поля ввода email и пароля.
   b. Отправка данных на сервер.
   c. Обработка ошибок (неверные данные, проблемы с сетью).
2. Создать экран списка сотрудников:
   a. Отображение имени, должности, контактной информации.
   b. Реализация поиска по имени/должности.
3. Реализовать экран профиля:
   a. Форма для редактирования контактных данных.
   b. Отправка обновленных данных на сервер.
4. Интеграция с API:
   a. Подключение токена авторизации к каждому запросу.
