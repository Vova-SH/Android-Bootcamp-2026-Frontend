# Техническое задание на разработку программного продукта для планирования встреч
## Команда: Цифровые Экзистенциалисты

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.


# User Stories / Use cases

## User Stories
1. Как сотрудник, я хочу зарегистрироваться в приложении, чтобы получить доступ к функционалу планирования встреч.  
2. Как зарегистрированный сотрудник, я хочу авторизоваться, чтобы пользоваться защищёнными разделами приложения.  
3. Как пользователь, я хочу редактировать свой профиль (имя, должность), чтобы мои данные отображались корректно коллегам.  
4. Как организатор, я хочу создать встречу с датой/временем и списком приглашённых, чтобы запланировать совещание.  
5. Как приглашённый, я хочу видеть список активных приглашений и быстро ответить «принял» / «не принял».  
6. Как пользователь, я хочу просматривать своё расписание (день / неделя / месяц), чтобы планировать рабочее время.  
7. Как пользователь, я хочу видеть валидацию времени (только часы), чтобы нельзя было создать встречу на произвольные минуты.  
8. Как пользователь, я хочу адаптивный интерфейс, чтобы приложение корректно выглядело на разных устройствах.

## Use Cases (Frontend)

### UC-01: Регистрация пользователя
**Цель:** Создание аккаунта через приложение
**Участники:** Новый сотрудник.
**Предусловия:** Пользователь не зарегистрирован

**Основной поток:**
1. Открыть экран регистрации.
2. Ввести email, пароль, имя.
3. Нажать «Зарегистрироваться».
4. Выполнить клиентскую валидацию (email, пароль >= 6).
5. Отправить POST `/api/auth/register`.
6. При успехе - переход к авторизации.

**Альтернативы:**
- 409 - email уже зарегистрирован.
- 400 - ошибка валидации.

---

### UC-02: Авторизация пользователя
**Цель:** Получение доступа к защищённым экранам.  
**Предусловия:** Аккаунт существует.

**Основной поток:**
1. Открыть экран логина.
2. Ввести email и пароль.
3. Сформировать `Authorization: Basic base64(email:password)`.
4. Сохранить credentials в защищённое хранилище.
5. Перейти в основной раздел приложения.

**Альтернативы:**
- 401 - неверные данные.
- Ошибка сети - показать сообщение.

---

### UC-03: Редактирование профиля
**Цель:** Обновление имени и должности.  
**Предусловия:** Пользователь авторизован.

**Основной поток:**
1. Открыть экран профиля.
2. Изменить имя и/или должность.
3. Нажать «Сохранить».
4. Отправить PATCH `/api/profile`.
5. Обновить данные в UI.

**Альтернативы:**
- Пустое имя - клиентская ошибка.
- 401/403 -> выход на логин.


### UC-04: Создание встречи
**Цель:** Запланировать встречу.  
**Предусловия:** Пользователь авторизован.

**Основной поток:**
1. Открыть экран создания встречи.
2. Выбрать дату и час (минуты = 00).
3. Ввести название.
4. Выбрать >=1 приглашённого.
5. Выполнить клиентскую валидацию.
6. Отправить POST `/api/meetings`.
7. Показать подтверждение.

**Альтернативы:**
- Нет приглашённых -> ошибка.
- Сервер вернул 400 -> показать сообщение.

### UC-05: Ответ на приглашение
**Цель:** Принять или отклонить встречу.  
**Предусловия:** Есть активные приглашения.

**Основной поток:**
1. Открыть экран «Приглашения».
2. Выбрать приглашение.
3. Нажать «Принять» или «Не принять».
4. Отправить PATCH `/api/invitations/{id}/accept|decline`.
5. Обновить статус в UI.

**Альтернативы:**
- Статус уже изменён.
- Встреча завершена.

### UC-06: Просмотр расписания
**Цель:** Отобразить встречи за период.  
**Предусловия:** Пользователь авторизован.

**Основной поток:**
1. Открыть экран «Расписание».
2. Выбрать период (day/week/month).
3. Выбрать дату.
4. Отправить GET `/api/meetings/schedule`.
5. Отобразить встречи.

**Альтернативы:**
- Нет встреч - пустое состояние.
- Некорректный период - ошибка.

## Критические Acceptance Criteria
- Только часовые слоты (минуты = 00).
- Нельзя создать встречу без приглашённых.
- Authorization добавляется автоматически.
- 401 всегда приводит к logout.
- Расписание корректно для day/week/month.
