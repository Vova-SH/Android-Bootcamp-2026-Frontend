# Техническое задание на разработку программного продукта для планирования встреч

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## User Story and Use Cases
Цель: Создать учетную запись

Участники: Сотрудник (пользователь приложения)

Предусловия: Пользователь не авторизован, приложение установлено и запущено, есть подключение
к интернету

Основной поток: Пользователь открывает экран регистрации, вводит логин и пароль и нажимает
на кнопку подтверждения. Приложение выполняет валидацию полей, и, если она проходит
успешно, пользователь может нажать кнопку «Зарегистрироваться». Приложение отправляет данные на
сервер, он создаёт нового пользователя и отправляет успешный ответ. Пользователя автоматически
перекидывает на главный экран

Альтернативный поток: Если введены некорректные данные -> отображам сообщение об ошибке;
Пользователь с таким логином уже существует -> отображаем ошибку; Нет подключения к интернету
отображаем сообщение о проблеме с подключением к сети


Цель: Просмотреть список своих встреч

Участники: Сотрудник (пользователь приложения)

Предусловия: Пользователь авторизован

Основной поток: Пользователь открывает приложение и попадает на домашнюю страницу, где
видит точками расписание на текущую неделю. По умолчанию отображается расписание на текущий день.
Для просмотра расписания на другие дни текущей недели он либо тыкает по ним, либо листает при
помощи стрелочек. Для отображения расписания на месяц пользователь может нажать на название
месяца. Приложение запрашивает данные с сервера и отображает список встреч,
разбитых строго по часовым временным слотам

Альтернативный поток: Если на выбранный период нет встреч -> отображаем пустое состояние;
Ошибка при загрузке данных -> отображаем сообщение об ошибке на сервере или при подключении
к сети


Цель: Создать встречу и пригласить других сотрудников

Участники: Сотрудник (пользователь приложения)

Предусловия: Пользователь авторизован

Основной поток: Пользователь нажимает кнопку создания встречи и переходит на соответствующий
всплывающий экран. Он выбирает дату, время начала встречи, вводит тему встречи
и выбирает сотрудников для приглашения. После нажатия кнопки «Создать» приложение отправляет
данные на сервер. Сервер создаёт встречу и возвращает успешный ответ, после чего пользователю
выводится сообщение об успешно созданной встрече. Далее он переадресуется на домашний экран

Альтернативный поток: Если не заполнена тема встречи -> кнопка «Создать» неактивна;
Если в выбранное время уже есть встреча -> отображаем сообщение об ошибке


Цель: Просмотреть входящие приглашения на встречи

Участники: Сотрудник (пользователь приложения)

Предусловия: Пользователь авторизован

Основной поток: Пользователь открывает вкладку почты. Приложение запрашивает список
активных приглашений с сервера и отображает их в виде списка с основной информацией о встрече

Альтернативный поток: Нет активных приглашений -> отображаем пустое состояние;
Ошибка загрузки данных -> отображаем сообщение об ошибке на сервере или состояния сети


Цель: Принять или отклонить приглашение на встречу

Участники: Сотрудник (пользователь приложения)

Предусловия: Пользователь авторизован, в системе есть активное приглашение на встречу

Основной поток: Пользователь открывает вкладку почты, выбирает приглашение и нажимает
кнопку «Принять» или «Отклонить». Приложение отправляет ответ на сервер, сервер сохраняет
решение пользователя. После этого приглашение исчезает из списка, а в случае принятия
встреча появляется в расписании пользователя

Альтернативный поток: Ошибка сети при отправке ответа -> отображаем сообщение об ошибке
сети и просим пользователя попробовать позже;
Встреча была отменена организатором -> отображаем уведомление об отмене


## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.
