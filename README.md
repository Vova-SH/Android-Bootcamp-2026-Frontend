# Техническое задание на разработку программного продукта для планирования встреч

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.

## User stories

- Как сотрудник, я хочу зарегистрироваться в приложении, чтобы получить доступ к системе планирования встреч.
- Как сотрудник, я хочу авторизоваться в приложении, чтобы использовать все доступные функции.
- Как авторизованный пользователь, я хочу просматривать свой профиль, чтобы видеть личную информацию.
- Как авторизованный пользователь, я хочу редактировать данные своего профиля, чтобы информация обо мне была актуальной.
- Как пользователь, я хочу создавать встречи, выбирая дату и временной слот строго по часам, чтобы планировать рабочие встречи.
- Как пользователь, я хочу приглашать других сотрудников на встречу, чтобы организовывать совместную работу.
- Как приглашённый сотрудник, я хочу видеть список активных приглашений на встречи, чтобы управлять своей занятостью.
- Как приглашённый сотрудник, я хочу принимать или отклонять приглашения на встречи, чтобы подтверждать или отклонять участие.
- Как пользователь, я хочу просматривать своё расписание ближайших встреч на главном экране.

# Use Cases

## 1. Регистрация пользователя

**Актор:** Пользователь  
**Предусловие:** Пользователь не авторизован

### Основной поток
1. Пользователь открывает экран регистрации.
2. Вводит логин и пароль.
3. Нажимает кнопку «Зарегистрироваться».
4. Приложение отправляет данные на сервер.
5. Сервер возвращает успешный ответ.
6. Пользователь перенаправляется на экран авторизации.

### Альтернативные потоки
- **A1:** Введены некорректные данные  
  1. Приложение валидирует поля.  
  2. Отображается сообщение об ошибке.

- **A2:** Пользователь уже существует  
  1. Сервер возвращает ошибку.  
  2. Отображается уведомление пользователю.

---

## 2. Авторизация пользователя

**Актор:** Пользователь  
**Предусловие:** Пользователь зарегистрирован

### Основной поток
1. Пользователь открывает экран входа.
2. Вводит логин и пароль.
3. Нажимает кнопку «Войти».
4. Приложение отправляет данные на сервер.
5. Сервер возвращает данные об успешном фходе.
6. Учетные данные сохряняются локально для повторного входа.
7. Открывается главный экран приложения.

### Альтернативные потоки
- **A1:** Неверный логин или пароль  
  1. Сервер возвращает ошибку.  
  2. Отображается сообщение об ошибке.

- **A2:** Ошибка сети  
  1. Запрос не выполняется.  
  2. Отображается сообщение о проблеме соединения.

---

## 3. Просмотр и редактирование профиля

**Актор:** Авторизованный пользователь  
**Предусловие:** Пользователь вошёл в систему

### Основной поток
1. Пользователь открывает экран профиля.
2. Приложение запрашивает данные профиля.
3. Отображается информация пользователя.
4. Пользователь нажимает «Редактировать».
5. Вносит изменения.
6. Нажимает «Сохранить».
7. Приложение отправляет данные на сервер.
8. Профиль обновляется.

### Альтернативные потоки
- **A1:** Ошибка загрузки профиля  
  1. Сервер недоступен.  
  2. Отображается сообщение об ошибке.

- **A2:** Ошибка сохранения  
  1. Сервер возвращает ошибку.  
  2. Изменения не сохраняются, отображается уведомление.

---

## 4. Создание встречи

**Актор:** Авторизованный пользователь  
**Предусловие:** Пользователь вошёл в систему

### Основной поток
1. Пользователь нажимает «Создать встречу».
2. Выбирает дату.
3. Выбирает временной слот (строго по часам).
4. Выбирает участников.
5. Нажимает «Создать».
6. Приложение отправляет данные на сервер.
7. Встреча отображается в расписании.

### Альтернативные потоки

- **A1:** Ошибка создания  
  1. Сервер возвращает ошибку.  
  2. Изменения не сохраняются, отображается уведомление.

---

## 5. Просмотр приглашений и ответ

**Актор:** Авторизованный пользователь  
**Предусловие:** Пользователь приглашён на встречу

### Основной поток
1. Пользователь открывает список приглашений.
2. Приложение запрашивает приглашения.
3. Отображается список встреч.
4. Пользователь выбирает приглашение.
5. Нажимает «Принять» или «Отклонить».
6. Приложение отправляет ответ на сервер.
7. Статус приглашения обновляется.

### Альтернативные потоки
- **A1:** Нет активных приглашений  
  1. Отображается пустой экран.

- **A2:** Ошибка отправки ответа  
  1. Сервер возвращает ошибку.  
  2. Статус не изменяется, отображается сообщение.

---

## 6. Просмотр расписания

**Актор:** Авторизованный пользователь  
**Предусловие:** Пользователь вошёл в систему

### Основной поток
1. Пользователь открывает экран расписания.
2. Приложение запрашивает данные.
3. Встречи отображаются пролистываемым списком.

### Альтернативные потоки
- **A1:** Нет встреч  
  1. Отображается пустое расписание.

- **A2:** Ошибка загрузки данных  
  1. Сервер недоступен.  
  2. Отображается сообщение об ошибке.
