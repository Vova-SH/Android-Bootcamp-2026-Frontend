# Техническое задание на разработку программного продукта для планирования встреч

## Команда: 1511 строк кода

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.

# User Story
Как работник компании,
я хочу иметь возможность создавать встречи с коллегами, получать уведомления о приглашениях и просматривать своё расписание,
чтобы планировать рабочее время и координировать совместные мероприятия.

# Use Case: Авторизация сотрудника
Цель: Авторизация сотрудника для доступа к функционалу приложения.
Основные действия:
* Пользователь вводит email и пароль.
* Приложение отправляет данные на сервер.
* Сервер проверяет учетные данные и возвращает токен авторизации.
* Приложение сохраняет токен и переходит на главный экран.
Альтернативные события:
* Пользователь вводит неверные учетные данные.
* Сервер возвращает ошибку авторизации.
* Приложение отображает сообщение о неверных учётных данных.


# Use Case: Регистрация сотрудника
Цель: Создание новой учетной записи сотрудника в системе.
Основные события:
* Пользователь открывает экран регистрации.
* Вводит email, пароль, имя и фамилию.
* Приложение отправляет данные на сервер.
* Сервер проверяет уникальность email и создает запись в БД.
* Сервер возвращает подтверждение успешной регистрации.
Альтернативный события:
* Email занят.
* Сервер возвращает ошибку "Email уже используется".
* Приложение отображает сообщение об ошибке.

# Use Case: Создание встречи
Цель: Организация встречи с приглашением коллег.
Основные события:
* Пользователь нажимает «Создать встречу»
* Выбирает дату и временной слот 
* Вводит тему встречи
* Выбирает из списка сотрудников тех, кого нужно пригласить.
* Нажимает «Создать»
* Приложение отправляет запрос на сервер
* Сервер сохраняет встречу и отправляет приглашения всем выбранным сотрудникам.

# Use Case: Ответ на приглашение
Цель: Подтверждение или отказ от участия в встрече.
Основные события:
* Пользователь видит уведомление о приглашении.
* Переходит в раздел «Приглашения».
* Нажимает кнопки «Принять» или «Отклонить».
* Приложение отправляет ответ на сервер.
* Сервер обновляет статус участия и уведомляет организатора.
* Приложение добавляет встречу в расписание или убирает из списка.


# Use Case: Просмотр расписания встреч
Цель: Просмотр собственного расписания встреч в удобном формате.
Основные события:
* Пользователь переходит в раздел «Расписание».
* Выбирает представление: день / неделя / месяц.
* Приложение запрашивает список встреч у сервера.
* Сервер возвращает список подтвержденных встреч.
* Приложение отображает встречи в выбранном формате.
Альтернативный события:
* У пользователя нет встреч.
* Приложение отображает сообщение: «Нет запланированных встреч»



# Frontend 

# 1. Аутентификация и регистрация
Реализовать экран регистрации.
Реализовать экран авторизации.
Интеграция с API: отправка данных регистрации/авторизации.
Обработка ошибок.

# 2. Профиль пользователя
Экран редактирования профиля.
Загрузка текущих данных профиля при открытии экрана.
Отправка обновлённых данных на сервер.
Валидация обязательных полей.

# 3. Создание встречи
Экран создания встречи:
Выбор даты.
Выбор временного слота только по целым часам.
Текстовое поле для темы встречи.
Выбор сотрудников из списка.
Отправка данных на сервер.
Обработка успешного создания и ошибок.

# 4. Расписание встреч
Экран расписания с колонками: День / Неделя / Месяц.
Запрос данных у сервера при переключении вида.
Отображение только подтверждённых встреч.
Pull-to-refresh и индикатор загрузки.
