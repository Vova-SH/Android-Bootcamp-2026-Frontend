# Техническое задание на разработку программного продукта для планирования встреч

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)

Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## User Story
### Регистрация/Авторизация
* Как сотрудник компании, я хочу зарегистрироваться в приложении и войти в личный аккаунт
### Настройка профиля (Внутри приложения)
* Как сотрудник компании, я хочу редактировать свои личные данные, чтобы другие пользователи могли
  идентифицировать меня
### Создание встреч
* Как организатор встречи, я хочу создать встречу, выбрать участников и отправить им приглашения, чтобы они могли
  принять или отклонить приглашение
### Приглашение(Принять/Отклонить)
* Как приглашенный сотрудник, я хочу принять или отклонить приглашение на встречу, чтобы организатор узнал о моей
  занятости
### Просмотр списка приглашений
* Как сотрудник компании, я хочу видеть список приглашённых сотрудников. чтобы знать, кто будет присутствовать на
  встрече
### Просмотр собственных встреч
* Как сотрудник компании, я хочу просматривать своё расписание встреч, чтобы планировать рабочее время

## Use Cases

#### Регистрация/Авторизация
* Цель: Получить доступ к системе через личный аккаунт
* Пользователи: Сотрудники компании
* Предусловия: Учётная запись создана
* Основной поток: Пользователь вводит логин/пароль -> Отправка на сервер -> Система даёт доступ
* Альтернативный поток: Неверные учётные данные -> Отобразить ошибку

### Настройка профиля (Внутри приложения)
* Цель: Изменить данные сотрудника
* Пользователи: Сотрудники компании
* Предусловия: Изменение данных
* Основной поток: Меняет определённые данные-> сохраняет -> Данные отправляются на сервер -> Сохранено успешно
* Альтернативный поток: Ввод некорректных данных -> Сообщение об ошибке


### Создание встреч
* Цель: Создать встречу
* Пользователи: Организатор
* Предусловия: Создание встречи -> Отправка приглашений
* Основной поток: Выбирает время  и участников -> Отправляет приглашения
* Альтернативный поток: Некорректные данные/У сотрудника есть другая встреча в это время -> встреча не будет создана и
  придёт сообщение об ошибке


### Приглашение(Принять/Отклонить)
* Цель: Ответить на встречу
* Пользователи: Сотрудники компании
* Предусловия: Принять или отклонить приглашение
* Основной поток: Заходит в "Календарь" ( календарь со списком встреч) -> Нажимает на встречу -> Принимает/Отклоняет
  встречу -> Организатор получает уведомление
* Альтернативный поток: Приглашение истекло -> Приглашение удаляется

### Просмотр списка приглашений
* Цель: Просмотр списка участников встречи
* Пользователи: Сотрудники компании
* Предусловия: Сотрудник посмотрел на список
* Основной поток: Нажимает на встречу -> Далее нажимает на кнопку "О встрече" -> Перенаправление на окно с информацией
  об участниках и другой информации
* Альтернативный поток: Встреча не создана или список пустой

### Просмотр собственных встреч
* Цель: Просмотр собственных встреч
* Пользователи: Сотрудники компании
* Предусловия: Перейти в "Календарь"
* Основной поток: Выбирает период(день/неделя/месяц) -> видит встречи
* Альтернативный поток: Нет Событий

## Задачи


1) Форма аутентификации и профиля
2) Форма создания встречи
3) Календарь собственных встреч  
4) Страница деталей встречи и управление приглашениями  
5) Адаптивный UI с уведомлениями и навигацией
